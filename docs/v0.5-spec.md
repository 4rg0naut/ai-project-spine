# v0.5 change-spec — the knowledge layer

Plain-language plan for what v0.5 merges and why. Every section names the
real incident that earned it. Backward compatibility rules are at the
bottom; they are not optional.

## 1. STATE weight cap + `archive`

STATE.md is the resume file: every session re-reads it first. When it
fattens, every session pays for it. Measured on 2026-11-14: the live
Zelda3_port STATE.md weighs **752 lines** (adopt dry-run reported it the
moment v0.5 verify touched a skeleton copy) — the exact failure mode the
Zelda3 harness comment called out ("the next-command block grew to ~400
lines"). AI_dev's doctrine ("STATE.md routes to the truth table; ends
with the literal next command") only works while the router stays small.

Merge: `verify` reports the line count; over 120 it WARNS (never fails)
until the project opts in with a `state-cap: strict` line in
DECISIONS.md, after which it fails. New verb `archive` moves dated blocks
to `docs/STATE-LOG.md` byte-exact (the NCM/silicon-ledger STATE-LOG
supersession pattern), keeps the next-command block last, re-attests.

## 2. `db` clerk verbs over `data/db/records.jsonl`

Projects accumulate small machine facts — "the ROM's sha256 is X",
"patch target is head.bin" — and today they rot in markdown prose where
nobody re-checks them. silicon-ledger learned this the hard way: results
scattered across ad-hoc READMEs needed the master_index rewrite; the
spine's own v0.3 lesson (BUG-002: a verdict pointing at nothing,
silently) says machine records must be schema-validated or refused loud.

Merge: `db add|get|link|supersede|list`, append-only snapshots, one
malformed line stops every verb with exit 2 and a byte-identical file,
each accepted write attests + prints a receipt sha, verify re-runs after
the write, and a failing gate marks the fresh record `void` with a
retraction event instead of leaving it standing uncounted.

## 3. Preflight widened over tools + data (+ vault)

Rule R7 already greps claims/TODO/artifacts before funding work. The
incident that born it (AI_dev `ncm-run/docs/incidents.md`
**BUG-BRANCH-BLINDNESS**, 2026-10-24: two branches, 47-vs-30 divergent
commits, each side re-derived the other's settled work) has a second
face: the duplicated work was usually a TOOL or a DATA file, and neither
surface was greppable. silicon-ledger's re-derived instruments confirm
the same surface.

Merge: `preflight` also greps `tools/REGISTRY.md`, the directories in
`SPINE_DATA_DIRS` (default `data/`) and `vault/`. Hits still exit 2
until `--reason`.

## 4. Tool registry (`tools/REGISTRY.md`)

silicon-ledger ships `tools/TOOLS.md` — an instrument registry with
`canonical | duplicate | superseded` status — because instruments there
proliferated silently (three capture scripts, two provenance headerers).
Zelda3_port carries 35 tools with no registry at all.

Merge: `init` seeds `tools/REGISTRY.md` (path | status | purpose);
`verify` lists any executable in `tools/` absent from the registry as a
WARNING (never fails in v0.5.0 — same learning-curve rule as
ORPHAN-COVERAGE in v0.4).

## 5. Measured-results ledger (`measure`)

The NCM program's iron law: "cost tables carry params + ms + J +
train-seconds together" (PROGRAM.md §2) — a number without the run that
produced it is decoration. Zelda3_port proves the payoff: golden captures
(func_harness FAIL 0 / PASS 1668) are re-run, not remembered, and
`dataset_build.py` is deterministic twice over.

Merge: schema at `docs/measurement-schema.md`; `measure append` writes
`{value, unit, source_claim, command, observed}` after re-running the
command RIGHT NOW and refusing any claimed value that does not match what
it printed; `measure audit` re-runs every row (OK / DRIFT). Proof owed
by the build: one real Zelda3 golden recorded and audited green.

## 6. Promote ritual (`promote CLAIM_ID --to spine`)

v0.4 shipped "the mechanisms a live campaign earned" (commit d965396) —
but the harvest was invisible: lessons lived in each project's LESSONS/
and the fleet-memory scrape was manual (AI_dev fleet-memory doctrine).
Nobody could see what was pending promotion into the spine itself.

Merge: `promote CLAIM_ID --to spine` appends the claim + citations +
originating project to this repo's `INBOX.md`; unresolved ids exit 2.
INBOX.md is the standing review queue for future spine versions.

## Backward-compat rules (non-negotiable)

1. **The chain is sacred.** A v0.4-written ledger loads on v0.5
   unchanged; `claim emit --kind` adds a field, never rewrites events;
   v0.4 ledgers have no trust field and default to `asserted`. Proven by
   a permanent selftest case that re-inits with the embedded real v0.4.0
   file (deflated in `spine.py`), verifies the untouched tree, adopts it,
   and checks byte-identity + old-id resolution.
2. **`adopt` touches nothing that exists.** Pre-existing files stay
   byte-identical except the `tools/spine.py` copy it replaces; STATE.md
   is never touched; new parts land as new signed files. Zelda3_port
   (442 events, live v0.4 ledger) must pass `adopt --dry-run` with zero
   surprises, and `verify` green after.
3. **Exit-code contract unchanged.** 1 = a gate judged failure, 2 =
   refused (and refused writes touch nothing). New validation refusals
   (malformed record, measure mismatch, phantom promote) all exit 2.
4. **Warnings are free; failures are earned.** New noisy-but-unproven
   checks (UNREGISTERED tool, STALE derived view, STATE weight) WARN
   until a failure or an opt-in promotes them to gates — the v0.4
   ORPHAN-COVERAGE precedent.
5. **`tests/run.sh` untouched.** init seed changes must keep the old
   three-gate script green unchanged, or the adoption is not backward
   compatible.
